# DeepSeek Peak/Off-Peak Widget — durable memory

## Facts

- DeepSeek peak hours (UTC): `01:00–04:00` and `06:00–10:00`, Mon–Fri, **excluding
  Chinese public holidays**. Off-peak = everything else (half price). Peak = 2×.
- Brand color: deepseek blue `#4D6BFE` / `#4D6BFF` (whale asset uses `#4D6BFF`).
- OneWeb blue `#02A0E2`; grey letters `#9C9D9D`.
- Default prices (per 1M tokens): flash in-miss $0.15/$0.30, out $0.60/$1.20;
  v4-pro in-miss $0.66/$1.32, out $1.98/$3.96. Cache-hit lines omitted by decision.

## Decisions

- Native feature plugin for permanent/always-visible widget (final surface =
  **sidebar navigation entry + native page**, not a dashboard widget).
- Param file = JSON; 6h ± 15 min refresh; silent last-good on failure.
- Logos pixel-based PNG (transparent), not vectorized — per OverLord.
- OneWeb mark = full wordmark, square canvas + 5% border; linked to https://oneweb.hu.
- Countdown single color (green=off-peak, red=peak), updates every minute; no blinking.
- Status dot: red=not-fetched/default, green=last fetch succeeded; no text label.
- Author = OverLord.

## Final architecture (what actually works — read carefully for maintenance)

A native **sidebar page** (always-visible navigation entry → native page), built
with the official `openclaw plugins build`:

- **Backend** (`src/index.ts`): `defineFeaturePlugin` + `defineFeatureContract`
  (`src/contract.ts`) exposing two operations — `status` (query) and `refresh`
  (action) — using TypeBox schemas. The plugin also registers a background
  `api.registerService` (`deepseek-peak-widget-refresh`) that starts the
  `ParamsRefresher`. Return handlers `{ status, refresh }` from `setup(api)`.
- **Browser** (`src/control-ui.ts`): `defineControlUiPlugin` → `activate(host)` →
  `host.ui.registerNavigation({ id, label, page, icon })` + `host.ui.registerPage({ id,
  label, mount })`. Data read via `createFeatureClient(contract, host)` →
  `feature.invoke("status", {})`. Countdown re-fetches every 60s (light update).
- **Build**: `npm run build` → `tsc` + `openclaw plugins build` (produces the
  content-hash `controlUi` bundle; the CLI requires the feature/tool metadata, so
  **`defineFeaturePlugin` is mandatory** — `definePluginEntry` breaks the build).
- **Manifest** (`openclaw.plugin.json`): `uiCapabilities: ["page", "navigation"]`,
  empty `configSchema` (regenerated by build), `activation.onStartup: true`. No
  `dashboard` field (that's for dashboard widgets only).

### Critical pitfalls learned (do not repeat)

1. **Dashboard widget ≠ sidebar.** `registerWidget` + `surface:"widget"` +
   `dashboard.dataBindings` produce a *dashboard* widget that does NOT auto-appear
   and requires `registerGatewayMethod` + `definePluginEntry` — but `definePluginEntry`
   breaks `openclaw plugins build` (no tool/feature metadata). Dead end for "always
   visible".
2. **`registerPanel`** does not clearly surface in the Control UI upper-right rail;
   not the right choice for a persistent sidebar entry.
3. **Hand-esbuild** of the controlUi bundle produces a `dist/control-ui/control-ui.js`
   (no content-hash) that the Control UI does NOT load reliably. Must use
   `openclaw plugins build`'s content-hash output.
4. **Local `node_modules/openclaw`** dev-dependency creates a peer-link conflict
   (installer auto-repairs, but causes "memory-core-index stop timed out" drain
   errors on reinstall). Keep `openclaw` in devDependencies only.
5. **`Custom plugin UI` lab** (`gateway.controlUi.experimental.customPlugins`) must
   be enabled for the native UI of a user-installed plugin.
